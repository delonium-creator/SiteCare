## Известные ограничения облачной Cowork-сессии (не баги проекта!)

Эти вещи не работают из облачной сессии Claude (Home/Cowork) и это не связано с кодом проекта:

1. **`npm install` не может поставить `miniflare`/`wrangler`** — сетевая политика песочницы
   блокирует часть пакетов npm-реестра (`403 host_not_allowed`). Из-за этого 3 тестовых файла
   (`gateway.test.js`, `integration.test.js`, `platform.test.js`) не запускаются в облаке —
   на обычном компьютере или в GitHub Actions они отрабатывают нормально.
2. **`git push` из облачной сессии не работает вообще**, даже с personal access token —
   известный открытый баг Anthropic: proxy блокирует пуш в репозитории, не входящие
   в "authorized repository set" сессии, обхода пока нет.
   Issue: https://github.com/anthropics/claude-code/issues/76248
   Из-за этого изменения из облачной сессии в GitHub переносятся вручную (см. ниже).
3. Один тест (`assets.test.js` — "Windows launcher stays ASCII with CRLF") падает в Linux-среде,
   потому что `START-SITECARE.bat` сохранён в git с LF, а тест ожидает CRLF. На Windows это
   не всплывает благодаря `core.autocrlf`. Не исправлено — можно добавить `.gitattributes`
   (`*.bat text eol=crlf`), если понадобится тест зелёным везде.

## Как переносить изменения из облачной сессии в GitHub (пока баг с пушем не пофиксили)

- Маленькая правка (1-2 файла) — скопировать готовое содержимое файла и вставить через
  веб-редактор GitHub (Edit → Commit).
- Много файлов — Claude собирает их в zip, присылает файлом; на github.com:
  Add file → Upload files → перетащить содержимое zip → Commit.
- После переноса в облачной сессии сделать `git pull`, чтобы синхронизироваться.

## План перехода на автоматический деплой (GitHub Actions)

Workflow-файл `.github/workflows/ci-cd.yml` уже подготовлен (тесты на каждый push/PR,
деплой обоих воркеров при пуше в `main`). Он лежит локально в облачной сессии и ещё
**не перенесён на GitHub** — сделать это тем же способом (upload zip), что и с этим файлом.

Что нужно сделать один раз (руками, на GitHub и Cloudflare), чтобы деплой стал полностью
автоматическим и больше не требовал ни компьютера, ни ручного `wrangler`:

- [x] Перенести `.github/workflows/ci-cd.yml` на GitHub — файл лежал в корне репозитория
      и не подхватывался Actions; перенесён в `.github/workflows/ci-cd.yml` (2026-08-16).
- [x] Создать реальные D1-базы на Cloudflare и вписать их id вместо заглушек —
      оба id уже были созданы (`cdf0bcc2...` для основной БД, `4b2adca1...` для gateway),
      но после ручной загрузки файлов через веб-интерфейс GitHub перепутались местами:
      конфиг шлюза оказался в корневом `wrangler.jsonc` вместо основного воркера,
      а основной конфиг — в лишнем файле `wrangler (1).jsonc`. Разобрано и исправлено
      (2026-08-16): корневой `wrangler.jsonc` снова содержит конфиг основного воркера,
      `gateway/wrangler.jsonc` — конфиг шлюза с реальным id вместо `PUT_GATEWAY_DATABASE_ID_HERE`.
- [ ] В настройках репозитория GitHub → Settings → Secrets and variables → Actions
      добавить 4 секрета: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`,
      `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN` (вводить прямо на GitHub, не в чат)

После этого: любой пуш в `main` сам прогоняет тесты и деплоит оба воркера на Cloudflare —
проект "запускается" уже не локально, а как боевой сервис (Cloudflare Worker + Telegram-бот),
работающий постоянно, без участия компьютера разработчика.

## Про вкладку "Code" в приложении Claude

Отдельная от Cowork/Home сессия, работает через Remote Control, привязанный к конкретному ПК.
Не путать с этой (облачной) сессией — они не видят состояние друг друга.
На момент записи там наблюдалась ошибка `403 API Error: Failed to authenticate` — не связана
с git/GitHub, похоже на проблему авторизации самой сессии Code, не диагностирована до конца.
